# PrismatiX 0.1.0

The first public release of PrismatiX: a visual novel engine with a native
C++ Player, a TypeScript authoring toolchain and sandboxed JavaScript
extensions. It publishes npm packages that always share one version and pin
each other exactly. You install one of them, `@prismatix/cli`; it brings the
rest it needs:

| Package | What it is |
| --- | --- |
| `@prismatix/cli` | The `prismatix` command |
| `@prismatix/native-win32-x64`, `@prismatix/native-linux-x64`, `@prismatix/native-darwin-x64`, `@prismatix/native-darwin-arm64` | The native Player, Packager and Preview Host of one platform. The CLI lists all four as optional dependencies of exactly its version, and pnpm and npm install only the one for your machine |
| `@prismatix/web-player` | The experimental Web Player (WebGL2 and WebGPU renderers). Not installed with the CLI: a project that exports for the web adds it (`prismatix add web-player`) |
| `@prismatix/authoring-sdk` | Story compiler, validators and the JSX runtime for TSX screens |
| `@prismatix/runtime` | Types and a thin facade for runtime extensions |

```bash
pnpm add -g @prismatix/cli        # Node.js 22.15+; corepack enable pnpm
prismatix create my-game
prismatix dev my-game
```

npm works too: `npm install -g @prismatix/cli`, then
`prismatix create my-game --package-manager npm`.

## What is in 0.1.0

- **Story scripts** (`.pxstory`): dialogue, choices, conditions, variables,
  macros, input prompts, characters with expressions and layered portraits,
  stage and camera motion, transitions and effects, audio and voice, credits.
  Every executable line keeps a stable ID, so saves survive script edits
  (`prismatix ids --sync`).
- **Screens in TSX**: title, HUD, save/load, settings, backlog, gallery and
  custom routes, built from typed components and typed Player actions
  (`validate` rejects a misspelled action or argument). Nine-slice skins,
  transitions, hover scaling and data bindings.
- **Authoring loop**: `prismatix dev` replays the project in a live Preview
  after every save, keeps the last good revision on errors and points at the
  source line; `--at chapter2:120` starts anywhere.
- **Distribution**: `build`/`pack`/`release` produce a desktop game with the
  native Player: PDX5 archives (optional encryption and sharding), WebP/Opus
  transcoding, save migrations across versions, signed patches and overlays,
  optional content packs, and `Notices/` with every licence the game ships.
  The executable gets the game's name, icon (from a PNG or `.ico`) and version
  information; macOS gets a `.app` bundle and Linux a `lib/` folder and
  `.desktop` entry, and a Windows game keeps only its executable at the top
  level, with everything else in an `Engine` folder (`"layout": "flat"` keeps
  the older single-folder layout). A Windows game opens no console window.
  `pack --platform` packs for the other desktop platforms from any computer
  (`prismatix add platform` fetches their runtimes), with `.zip`/`.tar.gz`
  archives that keep the executable bit and macOS signing through rcodesign
  off a Mac.
  `pack --target web` (experimental) exports a static website that runs the
  same C++ Player through WebAssembly, with a WebGL2 (default) or WebGPU
  renderer.
- **Runtime extensions** in JavaScript or TypeScript (`prismatix extension
  create`): commands, Actions, events, saved state and logging in a QuickJS
  sandbox, with handler types generated from the manifest.
- **Importers**: Artemis games and screenplay drafts.
- **QA**: `prismatix test` drives a QA build of the Player with journey
  scripts (`click`, `jump`, `choose`, `screenshot`).
- **Sample**: `Samples/Starter` in the repository is the project PrismatiX
  Studio creates by default (the stock screens as TSX, the startup screen, a
  street background and two characters with a short opening scene); its
  README has the pnpm commands. Its pictures are AI-generated, supplied by the
  project owner for sample use only. It is not part of the npm packages.
- A VS Code extension for `.pxstory` (diagnostics, completion, navigation) is
  in `packages/vscode-pxstory`; it is not on the Marketplace yet.

The full list is in [CHANGELOG.md](../../CHANGELOG.md).

## Platforms

| Target | Status in 0.1.0 |
| --- | --- |
| Windows x64 | **Verified**: the native test suite, the packaged-Player journey and the clean-install author journey (global install, create, dev, build, packaged Player launch; pnpm and npm, ASCII and Traditional Chinese folder names) passed on Windows 11 before tagging, and run again in the release workflow. |
| Linux x64 | **Built and tested by the release workflow** (Ubuntu 24.04, Clang, Xvfb). Not yet exercised on a desktop machine. The runtime is built against Ubuntu 24.04's glibc and libstdc++, so older distributions may not run it. |
| macOS x64 and arm64 | **Built and tested by the release workflow** (macOS 15 runners). Not yet exercised on a desktop machine. The Player and tools are not signed or notarized. `pack` on a Mac signs the game's `.app` ad hoc, which runs on the machine that packed it; a game you distribute will be blocked by Gatekeeper until you sign it with a Developer ID and notarize it ([Distribution layout](../shipping.md#distribution-layout)). The `.app` layout is checked by CI, not yet on a desktop Mac. |
| Web | Experimental, both renderers. `pack --target web --web-renderer webgl2\|webgpu` uses the project's `@prismatix/web-player` (`prismatix add web-player`; built on Linux with Emscripten 6.0.5 by the release workflow). WebGL2 is the default and runs in browsers with WebGL 2. WebGPU uses an unmerged SDL WebGPU backend and needs a WebGPU browser. Both were played (title, first line, save/load) in headless Chrome and Edge with a hardware GPU on Windows; CI plays the Starter sample in headless Chrome on Linux (WebGPU there is best-effort on SwiftShader). Firefox, Safari and mobile browsers are untested. See [Web export](../web-export.md). |
| Android | Experimental. `pack --target android` needs the Android Player and SDK; see the shipping guide. |
| Consoles, iOS | Not supported. |

"Built and tested by the release workflow" means the release could not be
tagged unless that platform's native test suite and its clean install from
the published tarballs passed on GitHub's runners (the run is linked from the
release); it is not a claim about other machines.

## Requirements

- Authors: Node.js 22.15 or later (the release is tested with 24.14), and
  pnpm or npm. No C++ tools are needed. On Windows, avoid early Node.js 24
  releases: Node.js 24.2 crashes inside `fs.rmSync` for some folder names
  with CJK characters and spaces, which makes `pnpm install` (and so
  `prismatix create`) fail there; 24.14 does not.
- Players of a finished desktop game: nothing; Node.js is not needed.

## Known limitations

- Preview restarts the scene on every successful edit, even for text-only
  changes; it does not preserve live progress. Preview save slots are
  session-only.
- Deep project paths: the Player and Preview Host do not opt in to Windows
  long paths, so a project whose files lie more than 260 characters deep
  cannot be previewed or played on Windows.
- `dev` and `build` need no network after `create`, but `create` itself needs
  registry access to install the project's pinned tools.
- Desktop executables are unsigned on every platform.
- Packing for other platforms was checked by CI (Windows and Apple silicon
  packed on Linux, Linux packed on Windows) and on Windows with the release
  runtimes, by reading each archive; a cross-packed `.app` has not yet been
  opened on a Mac, nor a cross-packed `.exe` started on Windows. A Mac
  cannot pack a Windows build of a project with custom effects (no DXIL).
- **Web export** (experimental)
  - The WebGPU renderer is built from the unmerged SDL pull request
    libsdl-org/SDL#16020, pinned to one commit; SDL has no official WebGPU
    backend yet. A browser without WebGPU needs the WebGL2 export.
  - Movies on the WebGPU renderer play at about half the WebGL2 frame rate
    (each frame is copied through the CPU).
  - Custom effects need SPIRV-Cross and Naga 27.0.0 on the exporting machine;
    `@prismatix/web-player` does not carry these host tools.
  - `@prismatix/web-player` (both renderers, notices and source archives) is
    about 21 MB (46 MB unpacked); it must have exactly the CLI's version.
- Installing the CLI with `--no-optional` or `--omit=optional` leaves out its
  native package; the CLI then says which package is missing. Linux arm64,
  Windows arm64 and musl Linux have no native package.
- The package and document formats are revision 1 (PDX5 archives). Only
  revision 1 is read; later releases will say when that changes.

## Compatibility

This is the first release line. Extensions must declare a
`requiredEngineVersion` that includes 0.1.0, for example `">=0.1.0 <0.2.0"`
(what `prismatix extension create` writes). Development builds before this
release called themselves 0.2.0; an extension that requires `>=0.2.0` will be
rejected by 0.1.0 and must lower its range.

## Verifying downloads

Each GitHub Release carries the npm tarballs, the native runtime of each
platform (`prismatix-native-runtime-<version>-<platform>-<arch>.tar.gz`, the
same files as its `@prismatix/native-*` package), the debug symbols stripped
from the Linux and macOS binaries
(`prismatix-native-runtime-<version>-<platform>-<arch>-debug-symbols.tar.gz`:
`.debug` files for gdb on Linux, the unstripped binaries for lldb and atos on
macOS) and `SHA256SUMS`. The npm packages are published from the release workflow with
npm provenance; `npm audit signatures` verifies them after install.
