## 官方工作流參考與差異

Ren'Py 的 [Quickstart](https://www.renpy.org/doc/html/quickstart.html) 以 Launcher 建立可執行模板，提供預設存讀選單與故事/圖片編輯流程。PrismatiX 此次取相同作者目標，以 CLI 三指令準備可玩的 starter；目前仍需 native 互動及外部真人試作，不能把自動化 pass 當同等成熟度。

Ren'Py 的 [翻譯文件](https://www.renpy.org/doc/html/translation.html) 以 translation units / identifiers 管理對話翻譯。PrismatiX 的 stable IDs / source map 可支援改稿追蹤，但 Player 即時語言切換目前要求 operation topology 對齊；拆句、併句或插入演出需明確處理，不能套用另一引擎的語意。[Ren'Py 存檔文件](https://www.renpy.org/doc/html/save_load_rollback.html) 也明列哪些 Python 狀態不保存，因此比較應看各自保存邊界，而非籠統宣稱腳本狀態都能恢復。

KAG 官方文件描述 [scenario/素材準備](https://krkrz.github.io/krkr2doc/kag3doc/contents/Prepare.html)、[link 選項](https://krkrz.github.io/krkr2doc/kag3doc/contents/Diverge.html)、[label 區段的已讀管理](https://krkrz.github.io/krkr2doc/kag3doc/contents/ReadUnread.html)、[栞與 snapshot 注意事項](https://krkrz.github.io/krkr2doc/kag3doc/contents/SaveData.html)，以及 [trace/console 除錯](https://krkrz.github.io/krkr2doc/kag3doc/contents/Debug.html)。PrismatiX 同樣應讓故事、分支、存讀與錯誤位置直接可用；現有 Story/compiler contracts、typed Actions、TSX 與 extension providers 是不同設計，沒有證據可據此宣稱超越 KAG 的製作成本。

| 流程 | 責任 / 狀態所有者 | 邊界與錯誤處理 |
